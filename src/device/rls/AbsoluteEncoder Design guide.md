# 绝对值编码器速度计算算法设计文档

## 概述

`AbsoluteEncoder` 的速度计算算法，采用**高低速段混合策略**，满足以下需求：

1. **5个最小采样周期内跟踪**：在最大速度和最小速度范围内都能快速响应速度变化
2. **高低速段分别优化**：高速段防溢出，低速段提高分辨率
3. **平滑融合**：通过速度阈值在两个算法间平滑转换

---

## 举例说明

假设系统物理参数如下：

- 编码器分辨率: 16384 ticks/rev
- 最大机械速度: 5000 rpm
- 最小机械速度: 1 rpm
- 最小采样周期: 1 ms

换算成编码器刻度相关参数:

- 最大速度: (5000 rev/min) * (16384 ticks/rev) / 60 s = 136533 ticks/s
- 最小速度: (1 rev/min) * (16384 ticks/rev) / 60 s = 27.31 ticks/s

基于上述参数，计算出关键指标:

- 单周期最大位移: 最大速度 * 最小采样周期 = 136.5 ticks
- 单刻度最小时间: 1 tick / 最大速度 = 7.32 µs
- 单周期最小速度 = 1 ticks / 最小采样周期 = 1 ticks / 0.001 s = 1000 ticks/s = 1000 ticks/s / 16384 ticks/rev = 0.061 rev/s = 3.66 rpm
- 最小有效采样周期: 最小采样周期 / 最小速度 = 36.6 ms = 37 个最小采样周期

需确保单周期最大位移不溢出: 136.5 < 8192 (环绕范围的一半)

## 算法策略

为了全速度范围内都能实现稳定, 及时的速度跟踪, 设计了如下混合算法:

- **高速段**: 速度高于阈值时, 使用差分法计算速度
- **低速段**: 速度低于阈值时, 使用累计法计算速度


无论高速还是低速都使用低通滤波器平滑速度输出, 但不同的速度使用不同的滤波参数. 

- 高速段使用较高的截止频率, 以保证快速响应. 但仍需保证不引入过多噪声.
- 低速段使用较低的截止频率, 以提高分辨率和稳定性.

### 截止频率的计算方法

滤波器截止频率的选择需要在响应速度和噪声抑制之间取得平衡。

**高速段截止频率 $f_{c\_high}$**:

目标: 在 N 个采样周期内跟踪速度变化（如 N=5）

一阶低通滤波器的建立时间约为 3~5 个时间常数 $τ$,

- $τ = 1/(2πf_c)$
- 设建立时间 $t_{settle\_high} = N * T_{采样}$，则:
  - $τ ≈ t_{settle\_high} / 4$
  - $f_{c\_high} = 1 / (2π * τ) = 4 / (2π * N * T_{采样})$

以本例为例: $f_{c\_high} ≈ 4 / (2π * 5 * 0.001) ≈ 127 Hz$

**低速段截止频率 $f_{c\_low}$**:

低速时每个采样周期内位移往往小于 1 tick，需累计到足够位移(最起码1tick)再更新, 整个积累的周期称为`最小有效采样周期`。
目标: 在M个`最小有效采样周期`内跟踪速度变化（如 M=2）

- $τ = 1/(2πf_c)$
- 设建立时间: $t_{settle\_low} = M * T_{有效采样}$，则:
  - $τ ≈ t_{settle\_low} / 4$
  - $f_{c\_hlow} = 1 / (2π * τ) = 4 / (2π * M * T_{有效采样})$

计算方法和高速累计, 仅仅是用$T_{有效采样}$代替了$T_{采样}$, 用$M$代替了$N$

以本例为例: $f_{c\_high} ≈ 4 / (2π * 2 * 0.0366) ≈ 8.7 Hz$

**过渡区间**:
- 在速度阈值附近，使用线性插值混合两个滤波器的输出
- 过渡区间宽度建议为阈值速度的 ±20%


### 高低速切换策略（位移驱动优先）

为减少计算量, 并提高切换的稳定性, 采用基于**位移**的切换策略:

- 首先, 到本次采样的位移 < 1 tick, 必定触发低速段（累计法）;
- 否则, 根据位移大小决定使用哪种算法:
    - 当本次采样的位移 < 位移阈值（定义为速度动态范围 10% 折算到单周期的位移），使用“过滤阶段”算法，即按位移在线性插值融合高、低速输出。
    - 当本次采样的位移 ≥ 位移阈值，使用高速段（差分法）。

位移阈值建议: disp_thresh = 0.1 · (max_speed − min_speed) · T_s，且不低于 1 tick。


### 具体实现

1. **组件参数**

需要由用户配置的参数:

```cpp
struct AbsoluteEncoderConfig {
    // 编码器物理参数
    u32 resolution;              // 编码器分辨率 (ticks/rev). 

    // 速度范围 (单位: ticks/s)
    f32 maxSpeed;               // 最大速度
    f32 minSpeed;               // 最小速度

    // 采样参数
    f32 samplePeriod;       // 最小采样周期 (s)

    // 滤波器参数
    f32 highTrackingCycles;  // 高速段跟踪周期数 (采样周期数)，默认5
    f32 lowTrackingCycles;   // 低速段跟踪周期数 (有效采样周期数)，默认2
}
```

2. **组件接口**

```cpp
struct AbsoluteEncoder {
    
    void reset(u32 position, f32 speed);

    // 尽管编码器有分辨率限制, 但编码器的输出值不一定是根据分辨率折叠的, 如ABZ编码器的计数器值.
    // 采样周期按配置中的最小采样周期计算
    void update(u32 value, bool wrapped = false);

    // 尽管配置里给出了最小采样周期, 但实际采样周期可能会有变化, 因此每次更新时需要传入实际采样周期.
    void update(u32 value, f32 samplePeriod, bool wrapped = false);

    // 获取当前位置（单位: ticks）
    u32 getPosition() const;

    // 获取当前速度（单位: ticks/s）
    f32 getSpeed() const;

    // 获取换算后的角度值（单位: 弧度）
    f32 getAngular() const;

    // 获取换算后的角速度（单位: 弧度/s）
    f32 getAngularSpeed() const;
}
```
