# wibotlib 异步编程使用说明

## 概述

wibotlib提供了三种异步编程模型，用于处理非阻塞操作和线程间协作：

1. **AsyncSource/AsyncResult**：现代的异步结果模式，推荐用于新代码
2. **WaitHandler/WaitTrigger**：发送-接收异步模式，支持灵活的事件触发
3. **EventGroup**：底层事件同步机制，上述两种模型的基础

这些模型基于事件组池（EventGroupPool）实现，自动管理事件资源，避免手动创建和销毁EventGroup。

## 1. AsyncSource/AsyncResult 模式 ⭐推荐

这是最现代、易用的异步编程接口，类似于JavaScript的Promise或C++的future/promise。

### 基本概念

- **AsyncSource**：异步操作的提供者（类似Promise），由异步操作的执行者持有
- **AsyncResult**：异步操作的结果代理（类似Future），由调用者持有用于等待结果

### 核心API

```cpp
// AsyncSource - 异步操作的源头
class AsyncSource {
public:
    AsyncSource();  // 自动创建，自动管理资源
    ~AsyncSource();
    
    void setDone();                    // 标记操作成功完成
    void setError(Result result);      // 标记操作失败
    AsyncResult getResult(bool autoReset = false);  // 创建结果对象
};

// AsyncResult - 异步操作的结果
class AsyncResult {
public:
    // 工厂方法
    static AsyncResult fromOk();              // 立即成功
    static AsyncResult fromError(Result result);  // 立即失败
    static AsyncResult fromResult(Result result); // 根据Result创建
    static AsyncResult fromSource(AsyncSource& source, bool autoReset = false);
    
    // 等待完成
    Result wait(u32 timeout = TIMEOUT_FOREVER);
    
    // 移动语义（禁止拷贝）
    AsyncResult(AsyncResult&& other) noexcept;
    AsyncResult& operator=(AsyncResult&& other) noexcept;
};
```

### 使用场景 1：ADC异步采样

这是项目中的实际应用案例（来自`App/power.cpp`）：

```cpp
class Power {
public:
    // 开始异步ADC采样
    AsyncResult beginUpdate() {
        return adc.triggerSingleConversion();  // 返回AsyncResult
    }
    
    // 等待采样完成并处理结果
    void endUpdate(AsyncResult& ar) {
        Result rst = ar.wait(TIMEOUT_FOREVER);  // 阻塞等待
        if (rst.isOk()) {
            binning.update();  // 采样成功，更新数据
        } else {
            LOG_E("ADC sampling failed");
        }
    }
};

// 使用示例
void controlLoop() {
    Power power;
    
    // 触发异步操作
    AsyncResult ar = power.beginUpdate();
    
    // 可以在这里做其他工作...
    doOtherWork();
    
    // 等待完成
    power.endUpdate(ar);
}
```

### 使用场景 2：I2C异步读写

```cpp
class I2cSensor {
private:
    AsyncSource readSource_;
    
public:
    // 启动异步读取
    AsyncResult startRead(uint8_t reg, uint8_t* buffer, size_t len) {
        // 启动DMA传输
        i2c.startDmaRead(address, reg, buffer, len, 
            [this]() { readSource_.setDone(); },     // 成功回调
            [this]() { readSource_.setError(Result::kError); }  // 失败回调
        );
        
        return readSource_.getResult();
    }
};

// 使用
I2cSensor sensor;
uint8_t data[10];

AsyncResult ar = sensor.startRead(0x00, data, 10);

// 非阻塞：检查是否完成
Result rst = ar.wait(0);  // 立即返回
if (rst == Result::kTimeout) {
    LOG_I("Still pending...");
}

// 或阻塞等待
rst = ar.wait(1000);  // 最多等待1秒
if (rst.isOk()) {
    processData(data);
}
```

### 使用场景 3：立即返回结果

对于已经完成的操作，可以立即创建结果：

```cpp
AsyncResult validateInput(int value) {
    if (value >= 0 && value <= 100) {
        return AsyncResult::fromOk();  // 立即成功
    } else {
        return AsyncResult::fromError(Result::kInvalidParameter);  // 立即失败
    }
}

// 使用
AsyncResult ar = validateInput(50);
Result rst = ar.wait(0);  // 立即返回kOk，不会阻塞
```

### 自动重置模式

当需要重复使用同一个AsyncSource时，启用自动重置：

```cpp
class PeriodicSensor {
private:
    AsyncSource source_;
    
public:
    AsyncResult startSampling() {
        // autoReset=true: wait()后自动重置，可以再次使用
        return source_.getResult(true);
    }
    
    void onSampleComplete() {
        source_.setDone();  // 每次采样完成后设置
    }
};

// 使用
PeriodicSensor sensor;

for (int i = 0; i < 10; i++) {
    AsyncResult ar = sensor.startSampling();
    ar.wait(TIMEOUT_FOREVER);
    // wait()返回后自动重置，可以继续使用source_
}
```

### 状态机

AsyncSource内部维护三种状态：

```cpp
enum class State : u8 {
    kPending = 0,  // 等待中
    kDone,         // 成功完成
    kError,        // 失败
};
```

**状态转换**：
```
kPending --setDone()--> kDone
kPending --setError()--> kError

// 如果autoReset=true
kDone --wait()--> kPending
kError --wait()--> kPending
```

### 线程安全

- `AsyncSource::setDone()`和`setError()`可以在ISR中安全调用
- `AsyncResult::wait()`只能在线程上下文中调用
- 多个线程可以等待同一个AsyncSource（通过获取多个AsyncResult）

## 2. WaitHandler/WaitTrigger 模式

这是更灵活但稍复杂的异步模式，支持多对一的事件触发关系。

### 基本概念

- **WaitHandler**：接收者，等待异步事件完成
- **WaitTrigger**：触发器，由异步操作持有，用于通知完成

### 核心API

```cpp
class WaitHandler {
public:
    WaitHandler();
    WaitHandler(const WaitHandler& other);  // 支持拷贝（引用语义）
    ~WaitHandler();
    
    Result wait(u32 timeout);  // 等待触发
    Result reset();            // 重置状态
};

class WaitTrigger {
public:
    WaitTrigger();
    WaitTrigger(const WaitTrigger& other);
    ~WaitTrigger();
    
    void attach(WaitHandler& handler);  // 关联到Handler
    void detach();                      // 解除关联
    bool isAttached();
    
    void setDone();   // 触发成功
    void setError();  // 触发失败
};
```

### 使用场景 1：UART异步接收

```cpp
class UartDevice {
private:
    WaitTrigger rxTrigger_;
    uint8_t rxBuffer_[256];
    
public:
    // 启动异步接收
    void startReceive(WaitHandler& handler) {
        rxTrigger_.attach(handler);  // 关联Handler
        
        // 启动DMA接收
        uart.startDmaReceive(rxBuffer_, sizeof(rxBuffer_));
    }
    
    // DMA完成回调（在ISR中）
    void onDmaComplete() {
        rxTrigger_.setDone();  // 可以在ISR中安全调用
    }
    
    // DMA错误回调
    void onDmaError() {
        rxTrigger_.setError();
    }
};

// 使用
UartDevice uart;
WaitHandler handler;

uart.startReceive(handler);

// 做其他事情...
doOtherWork();

// 等待完成
Result rst = handler.wait(5000);  // 5秒超时
if (rst.isOk()) {
    LOG_I("Receive completed");
} else if (rst == Result::kTimeout) {
    LOG_W("Receive timeout");
} else {
    LOG_E("Receive error");
}
```

### 使用场景 2：多个触发器关联到一个Handler

一个WaitHandler可以被多个WaitTrigger关联，实现"任意一个完成"的语义：

```cpp
class MultiSource {
private:
    WaitTrigger trigger1_;
    WaitTrigger trigger2_;
    WaitTrigger trigger3_;
    
public:
    void attachAll(WaitHandler& handler) {
        trigger1_.attach(handler);
        trigger2_.attach(handler);
        trigger3_.attach(handler);
    }
    
    void source1Complete() { trigger1_.setDone(); }
    void source2Complete() { trigger2_.setDone(); }
    void source3Complete() { trigger3_.setDone(); }
};

// 使用
MultiSource multi;
WaitHandler handler;

multi.attachAll(handler);

// 等待任意一个完成
Result rst = handler.wait(TIMEOUT_FOREVER);
// 一旦任何一个trigger调用setDone()，wait()就会返回
```

### 使用场景 3：动态重新关联

WaitTrigger可以动态切换关联的Handler：

```cpp
WaitHandler handler1, handler2;
WaitTrigger trigger;

// 第一次操作
trigger.attach(handler1);
doAsyncOperation1();
handler1.wait(TIMEOUT_FOREVER);

// 第二次操作，切换Handler
trigger.detach();          // 先解除
trigger.attach(handler2);  // 再关联到新Handler
doAsyncOperation2();
handler2.wait(TIMEOUT_FOREVER);
```

### 重置和重用

```cpp
WaitHandler handler;
WaitTrigger trigger;

for (int i = 0; i < 10; i++) {
    handler.reset();  // 重置状态
    trigger.attach(handler);
    
    startAsyncOperation();
    handler.wait(TIMEOUT_FOREVER);
    
    trigger.detach();
}
```

### 自动解绑

- WaitTrigger析构时自动调用`detach()`
- WaitHandler析构时自动解除所有关联的Trigger

```cpp
{
    WaitHandler handler;
    {
        WaitTrigger trigger;
        trigger.attach(handler);
    }  // trigger析构，自动解除关联
    
    // handler.wait() 不会再被触发
}
```

## 3. EventGroup 底层机制

EventGroup是前两种模式的基础，也可以直接使用。

### 适用场景

- 需要复杂的事件组合逻辑（与/或）
- 多个事件标志的位操作
- 多个等待者等待相同事件

详细用法参见 [OS使用说明.md](OS使用说明.md#6-事件组-eventgroup)

## 4. EventGroupPool - 资源池

### 自动资源管理

AsyncSource和WaitHandler都使用EventGroupPool自动管理EventGroup资源：

```cpp
class EventGroupPool {
public:
    static EventGroupPool& getInstance();  // 单例
    
    Result fetch(EventGroupStub& eventGroup);   // 分配事件组
    void release(EventGroupStub& eventGroup);   // 释放事件组
};

struct EventGroupStub {
    EventGroup* eventGroup;  // 事件组指针
    u32 doneFlag;           // 成功标志位
    u32 errorFlag;          // 错误标志位
};
```

### 配置池大小

在项目配置中定义事件组池大小：

```cpp
// config.hpp 或 CMakeLists.txt
#define EVENT_POOL_SIZE 8  // 池中EventGroup数量
```

### 资源耗尽处理

如果池耗尽，`fetch()`会返回错误：

```cpp
AsyncSource source;  // 构造时自动fetch
if (source._eventGroup.eventGroup == nullptr) {
    LOG_E("EventGroup pool exhausted!");
    // 此时触发ASSERT
}
```

**建议**：
- 根据同时进行的异步操作数量配置池大小
- 及时释放不再使用的AsyncSource和WaitHandler
- 考虑使用立即返回的AsyncResult（不占用池资源）

## 5. 对比与选择

### AsyncResult vs WaitHandler

| 特性         | AsyncResult          | WaitHandler               |
| ------------ | -------------------- | ------------------------- |
| **易用性**   | ⭐⭐⭐⭐⭐ 简单直观       | ⭐⭐⭐ 需要理解attach/detach |
| **资源管理** | 自动（RAII）         | 手动（需要detach）        |
| **一对多**   | ✅ 支持（多个Result） | ✅ 支持（多个Trigger）     |
| **重复使用** | ✅ autoReset          | ✅ reset()                 |
| **ISR安全**  | ✅ setDone/setError   | ✅ setDone/setError        |
| **移动语义** | ✅ 支持               | ❌ 不支持                  |
| **推荐场景** | 大多数异步操作       | 需要动态重新关联          |

### 推荐选择

```cpp
// ✅ 推荐：简单的异步操作
AsyncResult readSensor() {
    return source.getResult();
}

// ✅ 推荐：立即返回的结果
AsyncResult validate(int value) {
    return value > 0 ? AsyncResult::fromOk() : AsyncResult::fromError(Result::kError);
}

// ⚠️ 特殊场景：需要动态重新关联
void dynamicCallback(WaitHandler& handler) {
    trigger.attach(handler);  // 动态关联
}

// ❌ 不推荐：过度使用底层EventGroup
void unnecessarilyComplex() {
    EventGroup eg;
    EventFlag flag = eg.fetchFlag();
    // 除非有特殊需求，否则用AsyncResult更简单
}
```

## 6. 完整示例

### 示例 1：ADC + 数据处理管道

```cpp
#include "os.hpp"
#include "async.hpp"

class AdcPipeline {
private:
    AsyncSource adcSource_;
    uint16_t rawValue_;
    
public:
    // 启动ADC采样
    AsyncResult startSampling() {
        HAL_ADC_Start_DMA(&hadc, &rawValue_, 1);
        return adcSource_.getResult();
    }
    
    // DMA完成回调（ISR中）
    void onAdcComplete() {
        adcSource_.setDone();
    }
    
    // 获取结果
    uint16_t getValue() const { return rawValue_; }
};

// 数据处理任务
class DataProcessor : public Worker {
private:
    AdcPipeline& adc_;
    
public:
    void run() override {
        while (true) {
            // 启动采样
            AsyncResult ar = adc_.startSampling();
            
            // 可以做其他事情...
            
            // 等待完成
            Result rst = ar.wait(100);
            if (rst.isOk()) {
                uint16_t value = adc_.getValue();
                LOG_I("ADC: %u", value);
                processData(value);
            } else {
                LOG_W("ADC timeout");
            }
            
            os::sleep(10);
        }
    }
};
```

### 示例 3：超时和重试

```cpp
AsyncResult retryableOperation(int maxRetries) {
    for (int i = 0; i < maxRetries; i++) {
        AsyncResult ar = startOperation();
        Result rst = ar.wait(1000);
        
        if (rst.isOk()) {
            return AsyncResult::fromOk();
        } else if (rst == Result::kTimeout) {
            LOG_W("Retry %d/%d", i+1, maxRetries);
            continue;
        } else {
            // 致命错误，不重试
            return AsyncResult::fromError(rst);
        }
    }
    
    return AsyncResult::fromError(Result::kTimeout);
}

// 使用
AsyncResult ar = retryableOperation(3);
if (ar.wait(0).isOk()) {
    LOG_I("Operation succeeded");
}
```

## 7. 最佳实践

### ✅ 推荐做法

```cpp
// 1. 使用AsyncResult作为返回值
AsyncResult startAsync();

// 2. 在ISR中设置结果
void HAL_ADC_ConvCpltCallback(ADC_HandleTypeDef* hadc) {
    source.setDone();
}

// 3. 使用合理的超时
ar.wait(1000);  // 而非TIMEOUT_FOREVER

// 4. 立即返回已知结果
return value > 0 ? AsyncResult::fromOk() : AsyncResult::fromError(Result::kError);

// 5. 使用autoReset重复操作
AsyncResult ar = source.getResult(true);
for (int i = 0; i < 10; i++) {
    ar.wait(TIMEOUT_FOREVER);
}
```

### ❌ 避免的做法

```cpp
// 1. 不要在ISR中调用wait()
void ISR_Handler() {
    ar.wait(100);  // ❌ 会触发断言
}

// 2. 不要忘记等待结果
AsyncResult ar = startOperation();
// ar被销毁，结果丢失 ❌

// 3. 不要过度阻塞
ar.wait(TIMEOUT_FOREVER);  // ⚠️ 可能永久阻塞

// 4. 不要在析构后访问
{
    AsyncSource source;
    ar = source.getResult();
}  // source析构
ar.wait();  // ⚠️ 未定义行为
```

## 9. 性能考虑

### 内存开销

- **AsyncSource**：~16字节（EventGroupStub + Result）
- **AsyncResult**：~16字节（指针 + 状态）
- **WaitHandler**：~20字节
- **WaitTrigger**：~8字节

### 时间开销

- `wait()`切换到挂起状态：~10-50µs（取决于RTOS）
- `setDone()`唤醒线程：~5-20µs
- 立即返回（`fromOk()`）：~几ns（无系统调用）

### 优化建议

```cpp
// 1. 对于确定性结果，使用立即返回
if (isValid(input)) {
    return AsyncResult::fromOk();  // 快速返回
}

// 2. 批量操作时重用AsyncSource
AsyncSource source;
for (int i = 0; i < N; i++) {
    AsyncResult ar = source.getResult(true);  // 重用
    ar.wait();
}

// 3. 避免不必要的等待
if (ar.wait(0).isOk()) {  // 先非阻塞检查
    // 已完成，立即处理
} else {
    // 仍在进行，稍后再检查
}
```
